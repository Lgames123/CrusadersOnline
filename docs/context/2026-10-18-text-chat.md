# Text chat with Local / Global / Server / Private tabs

Date: 2026-10-18 · Agent: Claude Code · Commit: Text chat: Local, Global, Server and Private tabs in a movable, resizable window

## Why
MMO chat: talk to your map, every map, one player, and read what the server reports (loot, gold, XP).

## Decisions and evidence
- Routing lives on the main thread (`SessionManager.chat`), not in the zone workers: local = sessions with the sender's `zone` (arena), global = every session in the world (in_world / zoning / transferring), private = character name, case-insensitive, first match.
- Server lines (`channel: 'system'`, `kind` loot / gold / xp / level / spell / quest / trade / error) are sent by `WorldZone.notify` from grantItem (gold, items), learnSpell, addExperience (+ level up), applyQuest gold, giveQuestItem, shopBuy / shopSell. Client-side SC.ERROR refusals ("Inventory full.") are also added to the Server tab.
- The sender gets its own copy with `sent: true` (every channel): the client tells "To X" from "From X" and doesn't make its own name a whisper link, without knowing its character name (`accountName` is the account, not the character).
- Control and format characters (`\p{Cc}\p{Cf}`) become spaces server-side (bidi overrides, newlines). Chat budget: 1 line/s, burst 5, per session; over it a notice, no disconnect (the 5/s control bucket still kicks before that).

## Deviations from the original
- All of it: the original is single player. Always on when online; hidden offline and during sequences.

## Not done / not decoded
- No chat history on the server, no mute/ignore/block list, no profanity filter, no party/guild channels.
- Guest names can repeat across restarts; private lines go to the first match.
- Kill XP / gold lines were checked by reading the code only; the browser check covered pickup (loot) lines.

## Gotchas
- The chat form has two text inputs and no submit button, so the browser never submits on Enter: `inputKey` handles Enter itself.
- `inputKey` stops propagation of every keydown, so the game's bubbling key handlers (input manager, hotbar, I, F1/F2, Esc menu) never see typed keys. Capture-phase listeners still do.
- Enter / NumpadEnter / Slash open the line only when not bound to a game action (`input.isBound`). Opening while pointer-locked exits the lock (`releasing`), and closing takes it back only when the chat took it (`chatTookLock`).
- Layout (x, y, w, h, minimized, tab) is in localStorage `crusaders.chat.layout`; with none saved, it opens in the bottom left corner.

## How to verify
- `pnpm --filter @crusaders/tests exec vitest run integration/chat` (local stays in its zone across a portal, global, private + echo, unknown name, rate limit).
- spells-server + spells-client, two guest tabs: Enter, type, Enter; `/g`, `/w <name>`, `/r`; drop and pick up a potion → Server tab "You receive 5 × Healing Potion."

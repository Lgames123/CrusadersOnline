# MMO hotbar: two rows of nine for potions, gear and spells

Date: 2026-10-18 · Agent: Claude Code · Commit: A two-row hotbar for potions, gear swaps and spells, with the original spell icons

## Why
User asked for a modern MMO action bar: 1-9 on row 1, a second row, potions / spells / quick gear swaps, rebindable keys, rows hidden from a small button, item slots as zoomed 3-D models, spells with the original game's art, names on hover.

## Decisions and evidence
- Row 2 is on **Shift+1-9**, not F1-F9 (user's choice): F1 / F2 stay the original's statistics / quest book. Hotbar bindings store combos as `Shift+<code>` (`comboCode`); a Shift press alone while rebinding waits for the next key. With Shift held and no Shift combo bound, the plain key is used (1 still works while walking).
- Spell icons are the original HUD spell wheel's: metatex.ctx `HUDSpell<Name>` → BASE `HUD<Name>` → `*Image=HUD<Name> FILE=Sp<Name>.tga` (exe strings at 0xEFB7C-0xEFC40). Mapping in `spell_icons.ts` (Revelation = SpRevelation, Soul Drinker = SpDrink, Spectral Ally = SpAlly…). Drawn cropped (scale 1.16) so the bronze ring is trimmed in the square slot.
- Item icons: `ItemThumbnails.getIcon` (square 96 px, key `icon_…`). Long items lie on the diagonal; for 2:1 and longer the view frames the end that spreads widest across the axis (sword guard / hilt, axe / mace / hammer head) and 60 % of the length from it (`iconFocus`). Checked on all 53 weapon / armour / shield / potion looks.
- Slots keep items by catalog `itemId` plus a snapshot (name, model, size), so a slot stays when the last one is used (greyed, red count). Potions: the smallest stack is drunk first. Gear: worn if none of that id is worn; a worn one is not taken off.
- Spells: a hotbar spell other than the selected one sends SELECT_SPELL then CAST_SPELL (same socket, ordered); the client check uses that spell's mana. R / T unchanged.
- Spells reach the bar from a new **Spells** page in the inventory (click selects for R, drag to the bar). Items drag from the bag / equipment onto a slot; a drop between slots or a non-hotbar item onto the bar does nothing (never a ground drop).
- Layout + visible rows per character in localStorage (`crusaders.hotbar.<characterId>`, guests share `guest`). Keys work for hidden rows too.

## Deviations from the original
- The whole hotbar and the Spells page are not original (always on; collapse it with − / ▾).

## Gotchas
- `#hotbar` must not get a `transform`: it becomes the containing block of the fixed tooltip / drag ghost (tooltip went off-screen).
- The bar only rebuilds its DOM when its markup changes: PLAYER_STATS arrives often and a rebuild between pointerdown and click loses the click. Classes added directly (drop highlight, drag) reset `html` after a drag.
- Clicks, drags and tooltips need the cursor (inventory open, Alt held, or unlocked).

## How to verify
- `pnpm test:unit` (keybindings.test.ts). Launch `spells-server` + `spells-client` (port 3101), play as guest, I → Spells, drag spells and the sword to the bar, press 1-9 / Shift+1-9 (mana drops, the spell gets selected), + / − / ▾ for rows, Options → Keybindings → Hotbar to rebind.

# Relay ops decoded: exits, mover and sound triggers, creature ops, use key

Date: 2026-10-16 · Agent: Claude Code · Commit: Relays run their decoded ops: exits, brushes, sounds, creature ops, use key, messages · Supersedes: 2026-10-16-script-fired-messages.md (its "Not done" on relay ops)

## Why
Relays (type 0x2B) were converted with only their op-8 → trigger/message targets; exit refs and
the other ops were ignored (follow-up of 2026-10-16-script-fired-messages.md).

## Decisions and evidence
- Loader switch 0x47852B: index = type − 3 (bytes 0x479958, jumps 0x47984C). Exit 0x13 → vtable
  0x4E1AC4, sound 0x0B → 0x4E1D58, mover trigger 0x1E → 0x4E1CE0. Objects sit in several type
  lists (every trigger is also in 0xD0): test membership per type, never "last type wins".
- Op 8 on an exit = 0x462890, the exit's level change (as crossed; `end` = the ending). Du2a's
  death relay → du9a #111, train 165226 (walk-in, 1 s) → Ws9a, Gl3c 72827 → gl4c. Server:
  `takeScriptedExit` uses the act's portal with that target + exit number for the crossing.
- Op 8 on 0x1E = 0x461B10: the brush at +0x38 gets its mover's use. Replaces the old
  "dword before the relay record" guess, which was **wrong** for Co2a/3a/4a/8a/9a and Ws2a–4a
  (those relays only run op 0 on the cell door: walking in no longer opens `bCellDoor3`) and
  missed Bs1a 232792 → `bnecrosdoor`.
- Op 8 on 0x0B = 0x461490: a sound at its points. Converted as `sounds` (feet, Z mirrored); the
  server broadcasts `SC.STORY_SOUND` (0x50) to the zone, the client plays it positioned.
- Creature ops (Ws5a only): 0x4102D0 queues brain events. 0x0A = event 0x18 (hostile takes the
  player at once, 0x40D910); 0x0B = 0x17 (prefer a creature); 0x0C = 0x19 (idle one attacks a
  creature now, 0x40C370); 0x0D = brain flag 0x400 (nearest opposing creature/player in sight,
  any range, 0x40DC90); 0x0E = disposition 4 (0x40CCD0). Converted as `creatureOps`.
- Use key: 0x460320 lets bit-3 triggers through for the player only while use is down. Only
  Ws1a/5a/9a's lever relays have it (same volume around `bLever1_1`); the server fires them from
  `interact` (any target) when the player stands in the volume.

## Deviations from the original
- Server creatures don't fight each other: attackTarget / preferTarget (creature targets) and
  disposition4 do nothing. fightNearest applies only toward players (hostile creatures notice
  players in sight at any range/angle until they respawn). Ws5a's guard-vs-skeleton fight is missing.
- Relays still fire once per character (story flags); the lever relay has no 0x200 in the original.
- The lever's `opens` guess (level.ts) still opens the gates too; the relay's use of an already
  moving gate is a no-op, so nothing doubles.

## Not done / not decoded
- Ops 0/1 (+0x0D bit 0): no reader found (byte scans: only getter 0x460240 = slot 9 and save/load
  touch it; no slot-9 call in the 0x0B / 0x1E code). Kept as `flagOps`, not applied. Ops 2/3 unused.
- Disposition 4's meaning; brain event 0x17's exact priority; Gl3c's activation 0x10000 relay
  (not walk-in: not fired by the server).
- No converter unit test for the op parser (checked against all 21 relays in the shipped caps).

## Gotchas
- `MANIFEST_VERSION` 1.23.0: reconvert and restart the server (train → Ws9a needs the new data).
- Arg type 0x14 is "any object" (the converter reuses `T_FLAG` for the constant).

## How to verify

- train: walk past the final door → Ws9a after 1 s. Ws5a: Tab on the lever → gates open, gate
  sound, skeletons come for the player.
